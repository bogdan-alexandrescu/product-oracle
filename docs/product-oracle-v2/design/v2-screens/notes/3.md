# Screen 3 · Evidence inspector for a PRD version (`evidence`, nav prds)

Shown as a third version tab (Document · Roadmap · Evidence) under the usual version header. Data: GET /v1/documents/{doc}/versions/{n}/evidence; add = POST …/section-links, remove = DELETE /v1/section-links/{id}.

## A · Section table + inspector (3-evidence-a.html, as approver)
- Idea: one row per SectionEvidence (heading, section_key, layer, link count, citation count, weakest confidence, stale count); the 380 px inspector shows the selected section's links (strongest first) and its draft citations, plus the Add-a-section-link form (kind, precision, target, claim).
- Trade-off: the most direct mapping of the API and the cheapest to build with existing DataTable/Inspector; the section text is not visible, so judging "does this link really support this paragraph" means switching to the Document tab.
- Shows: section_hash, level, layer, kind, precision, claim, module_key + composition_revision, current=false (stale), target ref/status/locked/confidence/excerpt/source_kind/url, restricted, source_removed, created_by/at, citation cite_key/source/ref/title/excerpt/retrieved_at (nulls). Filters: layer, has stale, no links/citations, ?section.
- Board: loading, ?section empty, section with nothing, 404, pinned 409, 422 x2, 403, partial (restricted/removed/rejected), no-excerpt citation, viewer/commenter/owner.

## B · Reading view with an evidence margin (3-evidence-b.html, as viewer)
- Idea: the version text on the left, an aligned margin of evidence cards per section (like comments); citation chips in the text are the existing CitationChip with its hover card; claim-precision links highlight their claim sentence.
- Trade-off: best for judging support in context and for viewers; needs the version body too (GET version, not part of the evidence payload), long sections make the margin uneven, and scanning the whole version for gaps is slower than a table. Adding a claim link via text selection is the most natural but needs the most front-end work.
- Shows: same link/citation fields as A, inline citation numbering, unsupported section in the margin, layer switch (Brief/Full).

## C · Coverage matrix (3-evidence-c.html, as owner)
- Idea: targets (baseline items, evidence/source items) and draft citations as rows, sections as columns; each cell is the link's kind + confidence tone, dashed for stale; an empty column flags an unsupported section. The inspector is target-centric: every section that links it, and "Link to another section".
- Trade-off: finds gaps and reused evidence at a glance; a target-first view is a client-side pivot of the payload (no new API). Weaker for reading excerpts and claims; wide (6+ sections) gets cramped, and on a phone it falls back to a list.
- Shows: kind, confidence, current, status (rejected/superseded greyed), locked, restricted, source_removed, per-section links · citations totals, module_key, created_by/at.

## Pick: A, with C's "unsupported" signal folded in
A maps 1:1 to the API (one SectionEvidence per row, links already sorted), handles every state cleanly, works as a phone list + sheet with no special casing, and its "No links or citations" filter covers the main point of C. B is a good later "Evidence" margin mode for the Document tab rather than a separate screen.

Shared classes: none needed.
