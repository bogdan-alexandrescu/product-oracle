# Product Oracle web

Next.js (App Router) review workspace for PRD drafts: documents, version view with
citation chips, anchored comments, per-section verdicts, feedback panel, diff,
approve and export. Typed against `lib/api/schema.d.ts` (generated by `make openapi`;
never edit it by hand) through `lib/api/client.ts`.

```bash
npm ci
npm run dev        # against the API on :8000 (proxied as /v1, see next.config.ts)
npm run dev:mock   # no backend: in-browser mock API with fixtures
```

## Mock mode

`NEXT_PUBLIC_API_MOCKS=1` (inlined at build time) swaps the client's transport for
`lib/api/mock/server.ts`, a fake of the `/v1` API backed by the fictional PRDs in
`lib/api/mock/fixtures.ts`. State persists in `localStorage`; the header's *Reset*
link reseeds it. Sign in with `admin@example.com` / `demo`.

## Tests

```bash
npx playwright install chromium
npm run test:e2e   # builds a mock-mode app into .next-mock and runs e2e/ against it
```

## Notes

- Comment anchors are W3C `TextQuoteSelector`s (`exact`, `prefix`, `suffix`) over a
  section's rendered text, excluding citation chips (`lib/anchor.ts`). Section bodies
  are rendered by `components/MarkdownBody.tsx` so highlights are placed by offset.
- With `cacheComponents`, Next keeps recently visited routes mounted but hidden, so
  DOM lookups are scoped to the view's root element.
